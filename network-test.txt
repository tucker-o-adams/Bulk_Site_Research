PART 3 - WHY THE URLs FAILED
======================================================================

Both environments route all outbound HTTPS through an allowlist proxy.
Package registries are allowlisted; arbitrary hosts are not.

  Allowed (cloud container NO_PROXY / allowlist):
    pypi.org, files.pythonhosted.org, registry.npmjs.org, jsr.io,
    index.crates.io, proxy.golang.org, api.anthropic.com, private ranges

  Allowed (desktop VM): pypi.org -> CONNECT returned "200 Connection Established"

  Denied: hazards.fema.gov, epqs.nationalmap.gov, fwspublicservices.wim.usgs.gov

That is why pip works and the ArcGIS / EPQS / NWI services do not. The three
hosts need to be added to the session egress allowlist (org / account network
settings) before any live NFHL, elevation-point-query, or NWI wetlands call
can succeed from either environment.

Until then, options for the TBDI / Mireye model:
  1. Add the three hosts to the egress allowlist.
  2. Pre-download the data (NFHL county GDBs, NWI state geodatabases, USGS 3DEP
     DEM tiles) onto the desktop and read them locally with geopandas -- both
     libraries are now installed and working in both environments.
